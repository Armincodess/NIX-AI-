        WHY NIX
      

      
AI coding agents need more than search.

      
Generic RAG dumps raw files into context windows. Nix provides structured, verified codebase intelligence.

    


    

      

        
01

        
Repository-aware

        
Nix understands the whole codebase as an integrated dependency graph rather than treating source files as disconnected text blobs.

      


      

        
02

        
Local-first

        
Your source code, index, embeddings, repository context, and memories remain strictly on your local machine with zero forced cloud uploads.

      


      

        
03

        
Source-grounded

        
Every answer, symbol, and architectural relationship is tied directly back to exact repository files and line numbers with proof.

      


      

        
04

        
Agent-ready

        
Built to empower external coding agents (Claude Code, Cursor, Cline, Antigravity) through the Model Context Protocol (MCP) rather than replacing them.

      


      

        
05

        
Deterministic

        
Research traces are recorded and cryptographically replayed over time to verify that conclusions remain valid as the codebase changes.

      


      

        
06

        
Developer controlled

        
No proprietary black boxes. Use Nix directly through a fast CLI, script it via headless JSON flags, or connect via local HTTP API.

        THE CLI
      

      
Everything starts from the terminal.

      
A fast, expressive developer CLI designed for automation and daily developer workflows.

    


    

      

        
$ nix setup

        
Auto-configure Nix MCP servers for detected coding agents.

      

      

        
$ nix init

        
Initialize a new Nix intelligence workspace in any repository.

      

      

        
$ nix index

        
Build local incremental repository intelligence and AST chunks.

      

      

        
$ nix search <query>

        
Fast hybrid lexical + semantic search across code and symbols.

      

      

        
$ nix ask <question>

        
Universal Context: Ask source-grounded questions with 90%+ context savings.

      

      

        
$ nix tree

        
Inspect repository module tree and file distribution.

      

      

        
$ nix doctor

        
Diagnose Nix environment, SQLite engine, and indexing health.

      

      

        
$ nix health --verbose

        
Audit repository intelligence health, dead code, and test coverage gaps.

      

      

        
$ nix mcp

        
Start stdio Model Context Protocol server for AI coding agents.

        QUESTIONS & ANSWERS
      

      
Frequently Asked Questions

      
Technical details on how Nix operates, indexes, and integrates with coding agents.

    


    

      

        

          
          

            Nix is a local-first context intelligence infrastructure layer for software codebases. It indexes your source files into a typed dependency graph, extracts symbols, captures Git commit timelines, and exposes source-grounded context to AI coding agents via CLI and the Model Context Protocol (MCP).
          

        


        

          
          

            No. Nix is not an agent and does not try to replace your existing tools. Instead, Nix acts as the intelligence and context layer underneath agents like Claude Code, Cursor, Cline, or Antigravity, feeding them precise repository context so they don't hallucinate.
          

        


        

          
          

            No. Nix operates locally by default. The SQLite index database (.nix/nix.db), embeddings, code chunks, and Git provenance stay stored directly on your machine.
          

        


        

          
          

            nix index scans your workspace, excludes ignored build/vendor files, parses AST declarations using Tree-sitter, builds a typed import/dependency graph, extracts semantic chunks, and persists them into a local SQLite database for fast retrieval.
          

        


        

          
          

            nix ask evaluates natural-language questions against the codebase. It parses developer intent (e.g. HOW, WHERE, ARCHITECTURE), extracts relevant topological symbols and files, and generates a token-compressed, source-grounded context package (typically saving 90%+ context tokens).
          

        


        

          
          

            Nix checks referenced file paths, symbol declarations, and relationships directly against the indexed AST. In addition, nix replay re-evaluates research traces against current workspace files to report a cryptographic Code Drift Score.
          

        


        

          
          

            Any tool or agent supporting the Model Context Protocol (MCP) or command-line scripting can use Nix, including Claude Code, Cursor, Cline, Google Antigravity, Windsurf, OpenCode, and custom internal agent pipelines.
          

        


        

          
          

            The Nix Playground is an interactive terminal interface that lets you test Nix commands directly against real repositories in your browser, viewing exact stdout, retrieved context, and AST line numbers.
          

        


        

          
          

            Yes. Run npm install -g nixai and execute nix init in any of your repositories. It requires Node.js >= 20 and has no external server prerequisites.
          

        


        

          
          

            The Playground currently demonstrates Nix against the Google zx repository. The displayed terminal results correspond to actual Nix execution against that repository commit (65fc542).
